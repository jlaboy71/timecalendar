1. Methodology

1.1 Oracle Pattern Verification

We implemented an independent oracle - a separate implementation of business rules derived directly from policy documentation. Each test compares production code output against oracle expectations:

oracle_result = PolicyOracle.calculate_expected_outcome(inputs) actual_result = production_code(inputs) assert oracle_result == actual_result

This pattern catches bugs where production code is wrong but tests pass because they encode the same incorrect assumptions.

1.2 Self-Scan Approach

Rather than assuming behavior, we scanned the codebase to extract actual rules:

  • Enumerated all PTO types from src/constants.py
  • Extracted balance formulas from src/models/pto_balance.py
  • Identified validation rules from src/services/pto_service.py
  • Located working day logic in src/utils/working_days.py

2.2 Core Invariants Identified

INV-001: Balance Calculation Formula
available = total + carryover - used - pending

Source: src/models/pto_balance.py:166-183

This invariant is consistently applied across all accruing PTO types (vacation, sick, personal, chicago_leave).

INV-002: Day-to-Hour Conversion
1 day = 8 hours (standard business day)

Source: src/services/balance_service.py:218

All balance fields store HOURS, not days. This was a previous bug that has been fixed.

INV-003: Working Day Definition
working_day = (weekday < 5) AND (date NOT IN holidays)

Source: src/utils/working_days.py:74

Monday=0, Friday=4, Saturday=5, Sunday=6. Holidays exclude "Early Close" entries.

4. Previously Identified & Fixed Issues

4.1 Session Storage Bug (Fixed This Session)

Issue: Global Session Storage Caused User Cross-Contamination

Root Cause: Application used app.storage.general which is shared across ALL users globally.

Symptom: When Tech User logged in from VPN, it overwrote Tech Manager's session on the local network.

Fix Applied: Changed all 26 files from app.storage.general to app.storage.user (per-session storage).
